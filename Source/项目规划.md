# 鼠鼠收尾人MOD：武器多形态系统项目规划

## 1. 目标

以“派送箱”为第一把原型武器，实现一件武器内部的多形态切换：

- 箱体模式
- 崩解锤
- 崩坏刃
- 多功能工具
- 后续可继续增加武器形态

切换不生成新物品、不销毁原武器、不改变物品的唯一身份。角色始终持有同一件武器，只改变当前形态对应的攻击、属性和显示效果。

武器栏中提供一个切换 Gizmo。点击后打开 Windows 浮动菜单，玩家从菜单选择目标形态。高功率模式为另一项独立技能，不与形态切换混为同一个状态。

## 2. 已核对的参考实现

### 2.1 原版 RimWorld 可直接利用的基础

原版武器通过 `ThingWithComps` 保存组件，通过 `CompEquippable` 管理攻击 Verb，通过 `VerbProperties` 描述攻击参数。装备栏从武器组件取得 Gizmo，攻击系统从装备组件取得当前主 Verb。

因此本 MOD 的基础应建立在以下原版链路上：

1. 武器定义声明组件和基础攻击。
2. 武器实例创建组件并保存当前形态。
3. 装备组件持有当前攻击 Verb。
4. 切换组件提供武器栏 Gizmo。
5. Gizmo 操作只修改当前武器实例的形态状态，并通知装备/攻击系统刷新。
6. 攻击、属性和绘制阶段读取当前形态结果。

原版没有直接提供“单件武器多形态”的完整组件，因此需要在原版组件接口上实现本 MOD 自己的形态控制器。

### 2.2 Milira 1.6 离子手枪

离子手枪使用 `AncotLibrary.CompRangeWeaponVerbSwitch`。它保存一个二态开关，点击 Gizmo 后把装备组件主 Verb 的参数替换为另一套参数，并刷新 Verb 和 Pawn 工作队列。

它证明了“同一件武器切换攻击参数”的可行性，但它依赖外部库，形态数量固定为两种，且主要切换射击参数，不是本 MOD 所需的多形态系统。

### 2.3 烟烬 1.6 Cinder_Dragonslayer

该武器使用自定义装备组件保存主/副攻击状态；切换时替换主 Verb 的参数，另以自定义武器类和扩展提供备用贴图。其 1.6 DLL 中存在形态切换与备用图形的独立实现。

它证明了攻击参数和武器图形可以随同一件武器的状态切换，但该实现依赖烟烬自己的组件、接口和自定义物品类，不应直接作为本 MOD 的运行时依赖。

## 3. 设计原则

### 3.1 运行时独立

最终 DLL 只依赖 RimWorld/Verse/Unity 必要程序集，不依赖 `AncotLibrary.dll`、`Embergarden.dll` 或烟烬、Milira 的程序集。

### 3.2 原版接口优先

优先使用原版 `ThingComp`、`CompEquippable`、`Verb`、`VerbProperties`、`Command_Action`、`FloatMenu`、`GraphicData` 和 `Scribe`。外部 MOD 只用于确认可行链路，不复制其类结构和命名。

### 3.3 形态是武器实例状态

形态必须保存在武器实例，而不是角色、基因或全局静态变量中。不同角色分别持有的同一种武器可以处于不同形态，掉落、转移和重新装备后仍保持该武器自己的形态。

### 3.4 切换时禁止静默损坏

切换必须检查形态数据、Verb 数据和图形数据是否完整。缺失必要配置时应在开发测试阶段报告错误，不能静默回退到错误攻击或持续生成无效状态。

## 4. 建议的系统结构

### 4.1 形态数据

在同一个武器组件属性的形态列表中配置所有形态。每个形态至少包含：

- 形态标识和显示名称
- 武器贴图路径或图形数据
- 远程/近战攻击参数
- 近战工具参数
- 形态专属属性修正
- Gizmo/菜单显示信息
- 是否允许在高功率模式下使用

箱体模式作为默认形态，形态编号固定从零开始。后续增加形态只增加 XML 数据，不修改切换主流程。

形态名称、描述、攻击参数、装备偏移和图形必须由当前形态状态统一提供。不能只通过多个 Patch 向基础 Def 追加攻击节点，否则原版信息卡仍会读取基础 Def，造成所有形态显示相同的名称、描述和静态面板。

### 4.2 武器实例组件

武器组件保存：

- 当前形态编号
- 当前高功率模式剩余时间或结束刻度
- 切换前后的必要运行时缓存

组件负责验证形态编号、执行切换、保存/读取状态，以及在武器生成、装备、卸下和读档后重新应用当前形态。

### 4.3 攻击实现

使用“单一武器实例 + 当前形态 Tool”的方式，不为每个形态生成新的武器物品，也不把每个形态拆成独立 ThingDef。

装备组件通过 `IVerbOwner.Tools` 返回当前形态的 tools，VerbTracker 从 tool+原版机动（Smash/Slash）生成单个主 Verb。切换时保留该 Verb 对象，重置后同步替换 `verbProps/tool/maneuver/loadID` 并恢复 caster；若当前 Verb 正在预热或爆发，则拒绝切换。

近战伤害、冷却、伤害类型全部由原版 Tool+机动提供，材质/品质倍率由原版链路处理；原版近战无预热（机动 `warmupTime=0`），形态差异化通过 `power`/`cooldownTime`/容量（伤害类型）表达。切换必须禁止在爆发/预热阶段直接替换参数，避免半个攻击过程使用旧形态、半个过程使用新形态；空闲时才执行切换。

### 4.4 武器图形

形态图形由武器组件根据当前形态返回。绘制应继续走原版 `Thing`/`Graphic` 链路，不修改 Pawn 渲染树。

当前形态还必须同步更新：

- 地面物品图标和地图物品图形
- 手持武器图形
- 背负/收纳图形
- 四方向贴图
- 形态切换后缓存是否刷新

信息卡通过武器实例的动态标签、描述和 SpecialDisplayStats 显示当前形态；基础 ThingDef 不再保留一套会覆盖所有形态的静态攻击 Verb。

如果某个形态只改变攻击方式而不改变外观，应允许该形态复用基础图形。

### 4.5 切换界面

切换 Gizmo 只在武器被玩家角色装备时显示。点击后弹出浮动菜单，菜单项显示：

- 形态名称
- 当前形态标记
- 简短的攻击/功能摘要
- 不可切换原因（例如攻击正在进行）

菜单操作直接调用武器组件的切换入口。界面层不直接修改 Verb、图形或存档字段，避免形成第二套状态逻辑。

## 5. 高功率模式

高功率模式是独立技能，不等同于形态。

执行链路：

1. 角色点击武器提供的高功率 Ability。
2. Ability 确认施放者当前装备的是目标武器。
3. Ability 添加一个持续时间固定的 Hediff 或等价原版状态。
4. 状态期间提供移动速度、操作/瞄准等计划中的修正。
5. 所有形态共享同一个高功率持续时间和冷却计时。
6. 持续时间内允许切换形态，切换只改变武器形态，不重置高功率剩余时间。
7. 状态结束后移除修正并进入冷却；切换形态不应重复添加状态或重新开始计时。

高功率效果的具体数值在实现前单独确认，不在规划阶段擅自确定。

## 6. 文件与工程安排

建议在 `Source` 下按职责拆分：

- 武器形态数据与组件
- 形态切换 Gizmo/浮动菜单
- 当前形态 Verb 或 Verb 刷新适配
- 图形读取与缓存
- 高功率 Ability/Hediff
- 共享工具和错误检查

现有工程的 `.csproj` 需要显式包含 `Source` 根目录新增的代码文件；不能依赖文件恰好存在于目录而自动编译。最终输出 DLL 后，应复制到 MOD 的 `Assemblies` 目录，并用当前 1.6 游戏环境测试。

## 7. 实施顺序

1. 先完成单武器、两形态、只切换攻击参数的最小闭环。（已完成）
2. 验证装备、卸下、掉落、转移、死亡、读档和重新装备后的形态状态。（存档/掉落/转移待边界回归）
3. 增加多形态菜单和形态状态显示。（已完成）
4. 接入不同形态的近战攻击、属性修正和信息卡显示。（已完成：原版 Tool 链 + Harmony 动态 DPS/AP）
5. 接入形态图形和手持/背负显示。（已完成）
6. 增加第四、第五形态，确认只需 XML 数据扩展。（后续武器待实现）
7. 最后接入高功率 Ability/Hediff，并验证其计时与形态切换互不重置。（已实现，实测正常）

## 8. 必须测试的边界

- 切换时武器正在预热或爆发射击（已测：预热已废弃，爆发/预热拒绝检查保留）
- 角色被迫停止、倒地、死亡或换武器（待边界回归）
- 武器掉落、被另一个角色拾取、进入容器和交易（待边界回归）
- 读档时处于非默认形态（待边界回归）
- 形态数据缺失或引用不存在的投射物/图形（代码会抛错/报错，不静默）
- 多把同类武器同时存在且形态不同（待边界回归）
- 高功率状态期间切换形态、状态结束、进入冷却（已实现，待高功率专项实测）
- 多种近战形态切换后攻击命令和信息卡是否正确刷新（已测：正常）

## 9. 当前结论

目标可以实现，但不应直接复制 Milira 或烟烬的组件。

最终方案应采用“原版武器实例组件保存形态 + 原版装备/Verb 链路刷新攻击 + 原版 Gizmo/FloatMenu 提供选择 + 原版 Graphic 链路显示形态”的组合。这样既保留 RimWorld 的装备和存档行为，又能支持派送箱的多种完全不同形态，并且不会把外部 MOD 的运行时依赖带入本 MOD。
