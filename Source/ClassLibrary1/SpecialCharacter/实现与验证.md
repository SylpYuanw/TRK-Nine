# 特殊人物派遣：实现与验证

更新：2026-10-13。目标版本：RimWorld 1.6。

## 玩家流程

殖民地通讯台联系鼠族王国 →「转接 Hana 协会：特殊人员派遣」→ 选择满天星 → 支付 2000 白银 → 等待约游戏内一小时 → 原版空投开舱，满天星直接加入，发送一次到达 Letter。

Hana 标识位于页面上方正中，下面按人物 Def 显示 FuFu 图标、姓名、所属协会与购买按钮。联系人为「Hana 协会派遣负责人」，只显示身份和固定回复；鼠族王国仍使用其原有外交和首领对象。

白银通过原版 `TradeUtility.AllLaunchableThingsForTrade` 统计本次通讯地图中通电交易信标覆盖的银堆，复用原版去重。页面强制暂停，只在打开及购买／退款操作后刷新余额；点击购买时重新核验。

等待时间为 `GenDate.TicksPerHour`，到期后发起普通 `DropPodIncoming`，使用正常下落耗时，不另实现精确计时。

## 唯一性和通知

世界订单按 `SpecialCharacterDef` 保存，状态依次为 Waiting → InFlight → Arrived，失败进入 Failed。只允许无订单的角色购买；角色死亡、离开、远行归来和多次通讯均不删除购买记录。

到达 Letter 只由本订单的专用空投舱成功放出人物后触发。提交通知前先写入 Arrived 与 `arrivalLetterSent`；重复完成不再取得通知资格。代码不监听 Pawn 的 `SpawnSetup`、地图进入或商队返回，因此远行归来没有再次触发入口。通知过程异常时明确报错，不自动重发。

首次加入填满实际适用需求。技能、经历、特质、外观、基因、装备只在首次生成时设置；加入后按游戏规则成长、受伤和更换装备，读档不重新应用人物配置。

## 保存所有权与失败处理

| 对象 | 保存位置 |
| --- | --- |
| 待派遣舱 | 世界组件的 `waitingPods` 深度保存 |
| 待派遣 Pawn | 舱的 `ActiveTransporterInfo.innerContainer` 深度保存 |
| 飞行舱及人物 | 地图上的原版 Skyfaller 容器保存；从 waitingPods 转移后不再双重保存 |
| 已加入 Pawn | 原版地图、商队、世界人物或尸体等正常保存；订单只留引用 |
| 扣取的白银 | 订单 `payment` 深度保存，成功加入后销毁 |
| 唯一购买与通知标记 | 世界订单保存，独立于 Pawn 是否仍存在 |

Arrived 与 Failed 都清除不再使用的舱和地图引用。Pawn 引用不启用 `saveDestroyedThings`，已销毁者可以恢复为空，购买标记继续有效。

读档时 `World.FinalizeInit(true)` 早于地图加载和交叉引用恢复，不能在该回调中核验 Pawn／舱／地图。订单校验与派遣时间表恢复由 PostLoadInit 安排到加载长事件结束后执行，此时 Scribe 引用和地图实体都已初始化，避免把尚未恢复的正常引用误判为损坏。

目的地消失、载体损坏、生成或开舱失败时，订单终止并记录明确错误。可用地图中退回白银；无法放置或地图已移除时，费用保留在订单里，之后通过任一殖民地的 Hana 页面领取。失败状态不在 Tick 中循环重试。保存前检查未完成订单的目的地，避免写入已被移除地图及其载体的悬空引用。

每 Tick 只比较下一次派遣时间，到期时才处理订单；没有全世界 Pawn 扫描。空投销毁先完成基类销毁，再报告尚未完成的订单，失败清理不会递归重复销毁同一载体。

人物放置、开舱声音、落地故事和舱体内容清理由原版 `ActiveTransporter.Tick/PodOpen/Destroy` 执行。专用舱只在原版销毁后检查本订单的 Pawn 是否已经到达目标地图，并提交完成标记及一次通知。

撤销尚未加入的生成时使用原版 `WorldPawns.PassToWorld(..., Discard)`。只调用 `Pawn.Destroy()` 会将该 Pawn 放入 WorldPawns；Discard 流程同时销毁装备、解除引用和清除人物，不留下失败生成的世界人物。生成函数通过输出引用立即把 Pawn 和待转入物品交给购买事务；初始化不再单独捕获异常，购买事务统一清理。

## 人物生成与依赖

满天星资料以 `pawnslots_提取核对.md` 为准。使用专用 PawnKind，关闭普通鼠族模板的口粮和随机装备，禁止复用世界 Pawn、随机亲属与额外年龄特质。`ForceNoGear` 与 `ForceNoIdeoGear` 阻止两个装备生成入口；意识形态和正常健康初始化仍由游戏处理。

固定清单包含 14 个内源基因，购买满天星需要 Biotech。没有该 DLC 时界面明确禁购，不将 Biotech 加为整个 MOD 的强制依赖。生成请求直接指定 `RK_XenoType_Ratkin`，原版异种提供 12 个常规基因，人物清单仅追加异种未包含的 `Skin_Melanin3`、`Hair_DarkReddish`。不再先生成 Baseliner 再修改异种身份。

`forcedEndogenes` 是追加清单，不限制原版产生其他基因。`Pawn_StoryTracker.SkinColorBase` 在无可用肤色基因时可添加随机基因，`GenerateGenes` 也会补充肤色、发色；首次固定外观初始化移除清单外的随机 Melanin／HairColor 基因，再验证最终清单。其他种族、能力或外源基因不被静默清除，真正不匹配时错误列出实际基因。

白银扣取使用 `stack.SplitOff(amount)` 后的无容器银堆，交给订单 `payment.TryAdd(Thing,bool)`。原版 `TryAdd(Thing,int,bool)` 在拆堆前会拒绝已有地图容器归属的对象；`TryAddOrTransfer` 转入 `TryTransferToContainer` 后也禁止直接从 Map 转移。整堆扣取会自动脱离地图，部分扣取保留原堆余额，订单继续负责深度保存和成功后的销毁。

技能先读取实际 Aptitude，再从最终目标反算基础等级并核验；采矿 4、种植 8 在 +4 资质下基础分别为 0、4，不重复加经历数值。派送箱走现有正常装备通知链路。

普通特质只配置在专用 PawnKind 的 forcedTraits 中，交由原版生成。移除原版额外随机生成的普通特质后核验固定清单，不维护第二份配置，也不在缺失时静默补填。指定极佳品质的物品缺少品质组件时明确报错，食物和白银的无品质状态按原版处理。

`TraitRequirement` 使用自定义 XML 解析，固定等级必须写成 `<Beauty>2</Beauty>`。`<li><def>Beauty</def><degree>2</degree></li>` 会被原版登记为名称 `Beauty2`，且没有等级；另外两项同理，人物 Def 的固定特质配置错误也是此解析失败的结果。2026-10-13 已修正三项 XML，无新特质 Def、补填或替代流程。

HAR 通过首次生成时的缓存反射调用 `OverwriteColorChannel` 和 `addonVariants`，不增加新的编译引用。写入 hair、skin、skinBase；尾巴、左耳、右耳 variant 均为 0。CE 的眼色字段来自 Facial Animation，缺控制器时白色是占位，不写入 HAR eyes 通道。

## 已完成验证及范围

- Release 编译成功，输出 `Assemblies/ClassLibrary1.dll`。
- `Source/Verification/Run-SpecialCharacterVerification.ps1` 通过：调用实际 DLL 的状态迁移、重复通知拒绝、终态不重新派遣、失败不循环、世界读档早期初始化及 XML 字段元数据检查；连同 XML 状态快照往返，共 213 项检查。固定特质回归调用原版自定义解析入口；白银回归执行原版 SplitOff 和 ThingOwner.TryAdd，覆盖整堆 500 与部分 175 的归属解除及金额守恒，隔离物品 ID／容器 UI 通知和地图网格初始化。另核对鼠族异种的 12 项基因与人物清单的两项外观差异。
- 54 项唯一 Def 引用、继承模板和两个图标路径核对通过。MOD／Ratkin 从实际 Def 目录建立索引，原版 31 项名称证据记录于 `Source/Verification/SpecialCharacter-CoreDefEvidence.json`，来源为 RIMSAGE；两个动态资质基因按已核对原版模板和技能名称验证。
- 人物 XML 与原始槽位核对通过：2000 白银、年龄性别、头型发型体型、经历、12 项技能与热情、3 项特质、14 个基因、6 件装备／库存，以及使用的中文文本键。

独立进程调用真实 Scribe 遇到 Unity 原生运行环境限制（`SecurityException: ECall 方法必须打包到系统模块中`）。现有快照验证使用 XMLSerializer，仅验证状态数据与迁移规则，不能证明 RimWorld 实际引用恢复、地图空投、Pawn 生成或 GUI 已通过。

验证程序的旧 .NET 编译器读取游戏类型元数据时产生 System.Span／ReadOnlySpan 引用警告，程序执行及检查通过；MOD 本身的 Release 编译无此警告。

独立验证改用本机 .NET 8 执行：原版解析器调用的 `String.Split(char, StringSplitOptions)` 不在旧 Framework CLR 中。仅在验证进程关闭依赖游戏 Prefs 的 DeepProfiler，原版解析及引用登记代码保持原样。

## 交付前自验结论

1. 创建时间：通过购买条件检查后、扣款前生成，符合任务书。页面打开、世界初始化和读档不生成。原版新生成结果不进入 WorldPawns；等待期间由深度容器持有，飞行后由地图载体持有。失败人物使用 Discard 清理，正常派遣不需要 KeepForever 或 GC 补丁。
2. 异常处理：本模块剩 3 处 catch，分别处理购买事务、发射和开舱失败，明确报错并停止该次订单；已删除人物、物品初始化两层重复捕获，清理由购买事务统一承担。另有 1 类退款补偿：能够放置时退回，不能放置时留存待领取。静默替代、重新生成、补发、旧字段迁移及本模块自动重试均为 0。
3. 设计取舍：复用原版异种生成、白银去重、SplitOff 拆堆、空投下落、开舱放人、声音、落地故事、装备通知和人物回收。保留的自定义逻辑限于固定人物资料、唯一订单、等待调度、扣款补偿、通知和界面；无精确空投计时、额外派系／首脑 Pawn、常驻待命人物、全世界扫描或余额轮询。
4. Def：三个新增 Def 名称均使用字母、数字和下划线，无重复；完整类名及派遣舱继承关系可识别。普通字段按实际类型元数据核对，defaultFactionType 对应原版 LoadAlias；固定特质按原版自定义解析实际登记的名称和等级核对。此前单看字段的检查漏检了错误语法，本轮补上这一验证入口，54 项引用检查通过。
5. 额外复看：逻辑自验通过后，经用户授权把人物 XML 和 Release DLL 同步到游戏实际加载的 Mods 目录，两文件 SHA256 均与工作区一致。通过 GABS／Rimbridge 重启到 Entry 主菜单，新 Player.log 中三条 TraitDef 引用错误及人物配置错误均消失，也无 SpecialCharacter 模块异常。AncientHeavyBridge 仍出现，按用户说明排除；本次额外复看仅覆盖启动加载，不代表殖民地派遣或实机存读档已经验证。

本轮购买链路修复后再次完成 Release 编译、213 项独立检查、原始人物槽／异种清单核对及两文件同步校验，随后经 Rimbridge 启动复看，新日志无特殊人物模块加载异常。购买中的基因不一致和白银归属问题由上述生成接口及拆堆链路修正；本轮未在玩家存档执行购买，启动结果不宣称已通过实机招募或空投验收。

## 可选游戏复看

1. 有可通讯鼠族王国的殖民地，从通讯台转接 Hana，检查标识居中、满天星 FuFu 图标和 2000 白银按钮。
2. 检查无通电信标、1999 银和 2000 银；重叠信标不重复计数，购买仅扣覆盖范围的 2000 银，满天星自带 300 银独立存在。
3. 购买后按钮变为派遣中，多次打开或在其他殖民地打开均不能再次购买；约一小时后正常空投。
4. 分别在等待、飞行、到达后保存并读档：同一 Pawn、同一订单；仅一次抵达 Letter，无重复扣款、补发或配置重置。
5. 检查外观、三个 addons、14 基因、三件极佳衣物、派送箱、饼干和最终技能；适用需求首次加入满值。
6. 派满天星远行后归来，期间及回来后分别读档，确认无第二次到达 Letter；死亡或离开后仍不可购买。
7. 等待／飞行期间移除目的地或销毁载体，检查错误只处理一次，白银退回或可领取；失败订单无持续 Tick 重试。
8. Biotech 未启用时界面禁购；Ideology 关闭时不写纹身和喜爱颜色字段，自动健康处理保留。
