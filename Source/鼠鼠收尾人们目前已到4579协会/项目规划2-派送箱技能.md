# 鼠鼠收尾人MOD：派送箱「高功率模式」技能实现规划（项目规划2）

> 拟实现对象：`Source/企划-2.md` 描述的派送箱技能「高功率模式」。
> 参考实现：Flugel 的 Shin（Ability+Hediff+开关切换）与 Defense_Shield（护盾）。
> 所有涉及原版机制的前提均已通过 RIMSAGE（MCP `tools/list`）核实，来源见各小节。

---

## 0. 目标（来自企划-2 的最终口径）

- 持续时间：游戏内 12 小时；期间可随时关闭。
- 冷却：游戏内 24 小时，**关闭技能时进入**冷却。
- 实现方式：Ability + Hediff + AbilitySwitch（开启/关闭两个技能切换式）。
- 一阶段：`StaggerDurationFactor=0` + `MoveSpeed +0.5`。
- 二阶段：技能时间=3 小时进入，额外获得 **50 点真实伤害上限**护盾，15 点/秒回复（60 tick，无受击冷却），只拦常规外部伤害（近战/远程/火焰等），**不拦手术伤害**。
- 三阶段：技能时间=9 小时进入，为随机部位添加**化学烧伤（质融器伤害）**伤口；豁免（不烧伤）：大脑/心脏/内部器官（肾、肺等）；以游戏内 45 分钟为间隔持续添加。
- 结束：技能时间=12 小时（严重度=100%）强制结束，直接处决持有者。
- 全部形态共用技能 CD 与持续时间；禁止切形态后技能能再次开启；形态切换后所有形态都变为“关闭”按钮。

## 1. 之前疑问的答复（已确认，含证据）

### 1.1 “质融器伤害”是什么 → 原版 `ChemicalBurn`
- RIMSAGE `search_defs("Chemical")` 命中 `[HediffDef] ChemicalBurn (label: "chemical burn")`。
- `get_def_details("ChemicalBurn")`：`HediffDef ParentName="BurnBase"`，`hediffClass=Hediff_Injury`（伤口类），带 `HediffCompProperties_TendDuration`、`HediffCompProperties_Infecter`（感染 0.3）、`HediffCompProperties_GetsPermanent`（永久疤痕）。
- “质融器”实体 = 原版 `DeathAcidifier`（胸口植入物）。来源：`Hediffs_BodyParts_Bionic.xml` 中 `DeathAcidifier` 的 `HediffCompProperties_DissolveGearOnDeath` 配置 `<injuryCreatedOnDeath>ChemicalBurn</injuryCreatedOnDeath>`，即携带者死亡时生成 3~6 处 `ChemicalBurn`。→ **三阶段灼伤伤口类型直接引用原版 `ChemicalBurn` HediffDef。**

### 1.2 “不拦截手术伤害”如何判定 → `DamageDefOf.SurgicalCut`
- 手术致伤链路全部走 `pawn.TakeDamage(new DamageInfo(DamageDefOf.SurgicalCut, …))`：
  - `Recipe_RemoveBodyPart.cs` L80、`Recipe_RemoveBodyPart_CutMany.cs` L27、`JobDriver_ExtractBioferrite.cs` L60。
- 护盾拦截时只要 `dinfo.Def == DamageDefOf.SurgicalCut` 就放行（不拦截），其余外部伤害才进护盾池。
- 说明：Flugel 护盾注释“手术伤害也能挡”是它拦所有 `PreApplyDamage`；本项目要求与它不同，必须按上述过滤。

### 1.3 Flugel 护盾的真实伤害模型（修正我之前的理解）
- Flugel `Defense_Shield`：护盾 Hediff 的 `HediffComp_ShieldEnergy`（`maxEnergy=76`）存的是**真实伤害条**；Hediff 阶段另有 `IncomingDamageFactor 0.5`（乘伤减免 50%）。因此等效可承受 **76 × 2 = 152** 点原始伤害。
- 原版“护盾腰带”是能量机制（10 伤害=30 能量）；Flugel 不同，它按真实伤害扣减、显示真实伤害条。
- **本项目的护盾**：50 点**真实伤害池**（非能量），15 点/秒回复、无受击冷却；只拦外部伤害、不拦手术。=> 采用“伤害池，吸收后溢出漏给受术者”的模型，不引入 IncomingDamageFactor（企划-2 未要求乘伤减免）。

### 1.4 能力挂载 → 武器级临时 Ability
- 现状证据：`Weapon_Box.xml` 里派送箱用 `<li Class="CompProperties_EquippableAbility"><abilityDef>RK_DeliveryBox_HighPower</abilityDef><compClass>XIYUNTE.CompEquippable_MultiForm</compClass></li>`；地狱猫类挂载也是武器级。
- RIMSAGE `CompEquippableAbility.cs`：`CompEquippableAbility : CompEquippable`，用 `AbilityUtility.MakeAbility(def, holder)` 在**武器组件**上持有一个临时 Ability，装备/卸下时 `pawn.abilities.Notify_TemporaryAbilitiesChanged()` 通知刷新，**不写入常规 pawn.abilities 列表**。
- 结论：开/关都走武器临时 Ability；切换不是真的增删 ability，而是 `CompEquippable_MultiForm` **按高功率状态决定显示“开”还是“关”**（参考 Shin 的开/关逻辑，但不搬到 pawn-level）。

### 1.5 严重度作为进度条 → 原版 `lethalSeverity` 致死
- RIMSAGE `Hediff.cs`：`HediffDef.lethalSeverity`（默认 -1）；`IsLethal` 要求 `lethalSeverity>0`；`Severity` 设值时 `value>=lethalSeverity` 会被 clamp 到 lethalSeverity 并置 flag；`CauseDeathNow()` 在 `Severity>=lethalSeverity` 时返回 true，由原版健康系统判死。
- 结论：主高功率 Hediff 设置 `lethalSeverity=1.0` 与 `maxSeverity=1.0`，自定义 HediffComp 每 tick 把 `Severity = elapsed / total`（12 小时 = 30000 tick），到 12 小时 Severity=1.0 → 原版判死（同感染/感冒 100% 致死，无需手写 `Pawn.Kill`）。

## 3. 实现方案

### 3.1 能力挂载与开启/关闭切换
- 武器 Def：保留现有 `<CompProperties_EquippableAbility>`，`abilityDef=RK_DeliveryBox_HighPower`，`compClass=XIYUNTE.CompEquippable_MultiForm`（即“开”能力）。
- `CompEquippable_MultiForm`：新增 `offAbility`（`AbilityUtility.MakeAbility` 创建 `RK_DeliveryBox_HighPower_Off`），并新增 `HighPowerActive` 判定（装备者身上是否存在主高功率 Hediff）。
- `CompGetEquippedGizmosExtra()`：高功率未激活 → 输出“开”能力 Gizmo；已激活 → 输出“关”能力 Gizmo；两种情况下都继续输出形态切换 Gizmo。
- “开”能力施放后不自动进 CD（`cooldownTicksRange=0`），改为“关”时统一 `StartCooldown(24h=144000 tick)` 到“开”能力。
- 这样切形态不触碰 Hediff/CD，全部形态都显示“关”按钮，从根上杜绝“切形态后再次开启”。

### 3.2 高功率主 Hediff（时间 + 阶段 + 严重度）
- HediffDef `RK_DeliveryBox_HighPower`：
  - `hediffClass` = 自定义 `Hediff_DeliveryBoxHighPower`（继承 `HediffWithComps`，可展示阶段标签颜色）。
  - `initialSeverity=0`，`maxSeverity=1`，`lethalSeverity=1`。
  - 3 个 stage：min 0 / 0.25（3h）/ 0.75（9h），每阶段都带 `StaggerDurationFactor 0`（statFactors）与 `MoveSpeed 0.5`（statOffsets），保证全程增益。
  - 自定义 `HediffComp_DeliveryBoxHighPower`（comps 列表）。
- 该 Comp 职责：
  - `CompPostMake`：初始化 `elapsedTicks=0`、`nextBurnTick`。
  - `CompPostTick`：`elapsedTicks++`；`parent.Severity = Clamp01(elapsed / 30000)`；触发二阶段加护盾（elapsed>=7500）、三阶段加灼伤（elapsed>=22500，每 1875 tick=45 分钟一次，以 `ChemicalBurn` 造 `Hediff_Injury` 加到随机非豁免部位）；到 12h Severity 到 1 由原版判死。
  - 提供 `Notify_Closed`/移除时清理护盾（手动关闭由“关”能力调用）。
  - `CompExposeData`：保存 `elapsedTicks`、`nextBurnTick`、`shieldAdded`、是否已加二/三阶段。

### 3.3 二阶段护盾（真实伤害池）
- HediffDef `RK_DeliveryBox_HighPower_Shield`：`hediffClass`=自定义 `Hediff_DeliveryBoxShield`，`isBad=false`，comps 含 `HediffComp_DeliveryBoxShieldEnergy`（`maxDamage=50`、`regenPerTick=0.25`=15/60）。
- `HediffComp_DeliveryBoxShieldEnergy : HediffComp`：
  - `damagePool` 起始=50；`AbsorbDamage(ref float dmg)` 扣真实伤害池并返回实际吸收量，溢出留在 `dmg`。
  - `CompPostTick`：每 tick 无受击冷却回 `regenPerTick`，封顶 maxDamage。
  - `CompExposeData`：存 `damagePool`。
- 伤害拦截：`[StaticConstructorOnStartup]` 安装 `Harmony` 前缀 Patch `Pawn.PreApplyDamage`：
  - `dinfo.Def == DamageDefOf.SurgicalCut` → 直接放行（不拦手术）。
  - 否则若持有该护盾 Hediff → `AbsorbDamage(ref dinfo.Amount)`，`dinfo.SetAmount(剩余)`（吸收完剩 0 则 Pawn 免伤；溢出则漏给受术者）。
- 关闭高功率时由主 Hediff 清理逻辑移除该护盾 Hediff。

### 3.4 三阶段化学灼伤
- 用 `ChemicalBurn`（原版）制造 `Hediff_Injury`，`Severity` 每次 = 可调值（初版设 5.0，可调），添加到随机部位。
- 豁免判定：只选外部/肢体部位，排除 `Brain`、`Heart` 与内部器官（肾/肺/肝/胃/肠/脊柱等）。
  - RIMSAGE `BodyPartDef` 无直接 depth 字段，故采用正向外表部位白名单：Torso/Arm/Hand/Leg/Foot/Neck/Shoulder/Head，天然排除内部器官；也可用排除集合。
  - 部位缺失（`PartIsMissing`）时跳过。

### 3.5 结束与冷却
- 手动关闭（“关”能力施放）：移除主高功率 Hediff + 护盾 Hediff，`StartCooldown(144000)` 到“开”能力；角色存活。
- 自然结束（12h / Severity=100%）：由原版 `lethalSeverity` 判死（处决），无需手写 kill。

### 3.6 数值汇总（可调，集中在一处）
- 总时长 30000 tick（12h）；二阶段 7500（3h）；三阶段 22500（9h）；灼伤间隔 1875（45 分钟）。
- 护盾最大真实伤害 50；回复 15/s（0.25/tick）。
- 关闭后冷却 144000 tick（24h）。
- 灼伤每次 Severity 初版 5.0。

## 5. 必须测试的边界
- 技能开启后切形态：CD/持续时间不变、不出现“关”之外的再次开启按钮。
- 手动关闭：护盾立即移除、`开`能力进入 24h 冷却、角色存活。
- 3h 护盾生效/回复；被近战/远程/火焰命中时按真实伤害池扣、溢出漏伤；被手术/医疗操作命中时不拦截。
- 9h 后每 45 分钟随机非豁免部位出现 `ChemicalBurn`；大脑/心脏/内部器官不出现灼伤。
- 12h 角色按 `lethalSeverity` 判死。
- 读档后 `elapsedTicks`/护盾池/灼伤间隔恢复正确。
