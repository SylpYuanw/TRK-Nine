# SpecialCharacter：特殊人物派遣任务书

更新：2026-10-27。阶段：现有模块已通过编译和自动验证，六位人物按各自 CE 数据配置。游戏复看属于额外步骤，结果见实现与验证文档。

## 目标与本轮范围

通过通讯台联系鼠族王国，再转接 Hana 协会，以白银请求特殊鼠族角色。Hana 联系人只有文字身份和固定回复，不生成联系人 Pawn。

当前上架九协会满天星、南部 Cinq 协会五桠果、南部 Seven 协会苍月草、南部 Liu 协会火焰兰、南部 Zwei 协会山荷叶、东部し协会精灵兰，六人均售价 2000 银。新人物复用现有生成、购买、空投和订单存档；配置及来源见 [五桠果与苍月草](新人物_五桠果_苍月草.md)、[火焰兰](HuoYanLan.md)、[山荷叶](ShanHeYe.md)、[精灵兰](JingLingLan.md)。界面使用已有 FuFu 图标；Mya FuFu 实体物品赠送联动列入后续任务。

身份、发型、发色、头型、经历、普通特质、技能目标、热情、基因、装备和物品默认固定。肤色使用已加载基因的正常结果，不以 CE 保存的黄色肤色覆盖纯白肤色基因。需求首次加入时填满，意识形态由原版分配；Hediff 不从 CE 导入，六人的专用 PawnKind 以原版 allowOldAgeInjuries=false 关闭生成时的随机旧伤和年龄旧病，基因、种族、装备及其他正常初始化继续由游戏处理。社交、记忆和历史记录使用正常初始化，不复制保存槽的世界状态。Facial Animation 六项面部类型及主副眼色按新 CE 导出固定，仅在 FA 与鼠族 FA 补丁同时加载时导入。

2026-10-12 更新：采用用户重新提供的 pawnslots.txt，当前配置与规则见 [pawnslots 提取核对](pawnslots_提取核对.md)。已移除 OA，改为鼠族异种 RK_XenoType_Ratkin、14 个内源基因；使用新文件的 Head1、发色、技能、极佳护目镜及库存白银 300。2026-10-13 最新规则：肤色保留纯白肤色基因结果，展示和派遣使用同一实际 Pawn。

## 联络实现

鼠族王国 Def 为 `Rakinia`。通过 `FactionDialogMaker.FactionDialogFor` 后置补丁，只在殖民地地图的王国通讯中添加 Hana 转接选项，随后打开独立派遣页。

派遣联系人独立于 `Faction.leader`，显示「Hana 协会派遣负责人」。问候、购买成功、余额不足、派遣失败和退款回复位于中文 Keyed 文件。Hana 参考资料说明其统筹各协会，但未指定总负责人姓名，因此本轮不虚构姓名。

通讯任务仍引用原有王国对象；Hana 只存在于转接后的界面。保留王国外交和现有首领，不创建隐藏派系或联络物品。

## 生成与存档

1. 为满天星建立独立的鼠族 PawnKind 和固定人物配置，避免修改通用鼠族角色或把她加入普通袭击、商队生成池。
2. 首次打开详情时使用原版 `PawnGenerator` 创建实际 Pawn，禁止复用随机世界 Pawn。年龄、性别等通过生成请求固定；经历、基因、普通特质确定后，刷新资质并按技能最终目标反算基础，再设置热情、经验和外观。经历在生成阶段的技能加成不重复累加，完成后逐项核验最终显示等级。
3. 控制原版自动装备与物品生成，逐件添加指定装备和物品。原版 `fixedInventory` 支持物品、数量、材料、品质和颜色，并会把武器与服装分别放入装备和穿戴栏，可作为固定装备配置的依据；完整方案需防止自动流程额外添加装备、口粮或药物。
4. 每个人物使用独立 PawnKind。首次联系 Hana 时建立空容器，首次查看详情才生成人物。购买前从容器内按 PawnKind 查找同一 Pawn，容器负责原版深度存档，不再维护 Def→Pawn 字典。购买后转入派遣舱，再转给地图上的原版空投载体；唯一购买状态由订单保存。
5. 正常读档仅恢复引用和状态，不重新生成、重置技能、补充装备、治疗或复活。已派遣角色再次购买时明确显示不可购买及原因。
6. 模组状态管理按首次查看、购买、存档和必要的角色事件处理，不加入每 Tick 全世界扫描。未查看的角色不生成；已查看且未购买的人物由容器持有，无世界 Pawn 常驻或保活补丁。

### 初始化与状态取舍

- 保留原版建立的 health、needs、relations、ideo、ThoughtHandler、MemoryThoughtHandler 等对象和集合。无指定内容只表示不导入额外条目，不能将 tracker 或集合赋为 null。
- 心情、饱食、休息等适用需求仅在首次加入时填满，不读取槽位小数，不永久锁满。
- 健康字段为空不触发统一清空 Hediff。专用 PawnKind 的原版 allowOldAgeInjuries=false 阻止生成阶段的随机永久伤口、截肢与年龄旧病模拟；基因、种族、装备及其他正常健康初始化继续执行。加入后的受伤与正常年龄变化由游戏处理，已生成的人物不自动治疗或重新生成。额外指定 Hediff／特性待用户说明。
- 意识形态交给原版分配，不导入保存文化、名称或未知扩展字段，不将自动分配误实现为无意识形态。
- 不导入空社交／记忆数据，不创建没有有效目标的社交记忆；生成时关闭随机亲属生成，保留有效的关系 tracker。加入后的正常社交和记忆按原版流程运行。
- 工作安排、记录、征召、原世界任务／对象引用等为保存快照，使用新殖民者的正常初始化，不搬入其他 MOD 的工作 Def。

人物仅在首次查看详情时生成。加入后不重新应用配置；已销毁的人物引用可以为空，永久购买记录仍保留。完成或失败时清除舱和地图引用，避免存档引用已销毁载体。

详情全身投影直接展示世界组件持有的实际 Pawn。返回和关闭只解除窗口引用，人物继续由世界组件保存；再次查看、购买、空投均复用该对象。首次生成尚未加入阵营，成功落地后由原版加入玩家流程初始化殖民者组件。发色在 HAR 颜色通道初始化后设置；肤色沿用基因。Facial Animation 面部六项及主副眼色在首次初始化前写入，之后由 FA 控制器随 Pawn 保存；正常读档不重新应用。

FA 数据来自 `D:\QQFL\pawnslots.txt` 第 45、19、53 字段。启用条件为 `Nals.FacialAnimation` 和 `fxz.Ratkin.FacialAnimation` 同时加载；配置保存字符串名称，未加载时不解析外部类型或 Def。固定类型为 Ratkin_Head、Ratkin_EyeStare、Ratkin_LidPointy、Ratkin_BrowNormal、Ratkin_MouthTooth、Ratkin_SkinNormal，主副眼色均为 (0.373,0.000,0.122,1.000)。本轮仅导入 FA 字段，新文件的普通头型 Head3 及其他人物数值不在本轮导入范围。

右侧介绍始终读取固定初始配置，不读取已派遣 Pawn 当前状态。资料行显示性别、年龄和种族，下一行显示专用 PawnKind 的固定特质，名称按原版特质等级及性别取得。技能等级与热情列表继续显示，仅移除「技能等级与热情：」说明文字。装备按默认品质色显示，下一行显示携带物品；唯一性提醒后换行加入「来自Hana协会的详细报告："故事"」，报告完整采用满天星.txt。余额和购买按钮使用原版白银图标。

## 白银购买与派遣

实际流程：进入派遣界面 → 点击详细信息，首次生成并保存实际人物 → 查看全身投影及固定初始资料 → 点击购买 → 校验余额、唯一购买状态与落点 → 将同一 Pawn 转入派遣舱 → 再次核验并扣款 → 保存等待订单 → 约一小时后空投 → 开舱加入并提交一次到达通知。

满天星售价 2000 白银，扣款限通电交易信标范围。等待使用 `GenDate.TicksPerHour`（2500 Tick），之后沿用原版空投下落，不另实现精确到达计时。

扣款与提交必须在点击确认时重新检查，不能只依赖界面打开时的余额。需防止反复点击或多个联络入口重复扣款、重复派遣。

扣取的银堆暂存在订单 `ThingOwner`，成功加入后才销毁。失败订单停止处理并报错，费用放回目标地图；地图已移除或无法放置时保存在订单中，页面提供领取退款按钮。已扣款形成的失败订单也保留唯一记录，不自动重试或重新生成。

世界没有可通讯的鼠族王国时，此渠道不可用。缺少必需 Def、配置不完整、角色引用异常等明确报错，不替换成人类、随机角色或反复重试。

## 后续任务：Mya FuFu 联动

检测 Mya FuFu 是否加载，在特殊 Pawn 首次派遣时附送对应协会／人物的一个 FuFu。

1. 下轮核对实际 packageId、FuFu Def、对象类型，以及各协会对应关系。

## 实现阶段验证

已完成：Release 编译；实际 DLL 的订单状态、通知资格与读档早期初始化验证；XML 快照往返；三个新增 Def 的类型及字段、54 项唯一 Def 引用、模板、图标、人物原始槽位数据和中文文本核对。固定特质另调用原版 `TraitRequirement.LoadDataFromXmlCustom` 核对名称与等级，不以普通字段检查代替自定义解析。最新 316 项检查已执行空组件的原版 Scribe LoadingVars/PostLoadInit，覆盖旧测试档的空状态；完整 Pawn 存读档及 GUI 仍需实机验收。

交付前五项自验结论、实现边界、证据及额外复看步骤见 [实现与验证](实现与验证.md)。逻辑检查先完成，以下项目可用于之后的游戏复看：

- 全新游戏首次派遣只有一个满天星，人物和装备逐项符合固定配置；不同新游戏的同一初始配置一致。
- 检查最终采矿 4、种植 8，正常基因资质均为 +4 时基础分别为 0、4；社交目标 15 不再次添加经历的 +6。其他技能也按最终目标校验。
- 无社交／记忆条目时组件及集合仍有效；自动意识形态和装备 Hediff 正常运行，适用需求首次加入满值。
- 白银足够／不足、确认时余额变化、重复点击和多个入口均不造成错误扣款或重复人物。
- 通讯者走向通讯台途中存档再读档，联系人引用和通讯任务正常。
- 派遣中及加入后存读档，Pawn 引用不变，不重置成长、装备、伤病与派遣状态。
- 已加入、死亡、离开及外部销毁后的角色不自动补发；明确区别正常结束状态和存档引用损坏。
- 派送箱正常提供现有形态、技能和背负表现；卸下及更换装备遵循现有逻辑。
- 必需角色 Def／材料／技能配置错误和没有可用落点时明确暴露失败，不遗留正常状态下的错误扣款。
