# 特殊人物派遣：实现与验证

更新：2026-10-13。目标版本：RimWorld 1.6。

新增五桠果与苍月草，均为 2000 银，复用同一派遣流程。只新增人物与模板 XML、图标引用、详细报告及可选发型 XML 替换；已有生成器的喜爱颜色改为配置字段。核对结果见 [新人物资料](新人物_五桠果_苍月草.md)。最新 Release 编译及 624 项检查通过，84 项唯一 Def 引用已核对。

## 玩家流程

殖民地通讯台联系鼠族王国 →「转接 Hana 协会：特殊人员派遣」→ 满天星「详细信息」→ 支付 2000 白银 → 等待约游戏内一小时 → 原版空投开舱，满天星直接加入，发送一次到达 Letter。

Hana 标识位于首页上方正中，下面按人物 Def 显示 FuFu 图标、姓名、所属协会与「详细信息」按钮。详细信息在同一窗口内作为二级页显示：左侧全身投影，右侧可滚动的固定初始资料，左下返回、右下购买。联系人为「Hana 协会派遣负责人」，只显示身份和固定回复；鼠族王国仍使用其原有外交和首领对象。

介绍不再放入人物卡的长悬浮提示。装备名称读取 ThingDef.LabelCap，品质读取原版 QualityCategory.GetLabel，显示「携带装备：名称（品质）」；下一行显示「携带物品：名称×数量」，唯一性提醒位于最后。所有介绍内容始终来自固定人物 Def，不随已购买 Pawn 的状态变化。参考 Quality Colors (Continued) 1.6 的 Default 配色，极佳为 #73ABFF；只参考颜色，不增加该模组依赖。富文本标签使用纯 string 拼接，TaggedString 先调用 ToString。余额及购买按钮通过 Widgets.ThingIcon 绘制 ThingDefOf.Silver。

白银通过原版 `TradeUtility.AllLaunchableThingsForTrade` 统计本次通讯地图中通电交易信标覆盖的银堆，复用原版去重。页面强制暂停，只在打开及购买／退款操作后刷新余额；点击购买时重新核验。

等待时间为 `GenDate.TicksPerHour`，到期后发起普通 `DropPodIncoming`，使用正常下落耗时，不另实现精确计时。

## 唯一性和通知

世界订单按 `SpecialCharacterDef` 保存，状态依次为 Waiting → InFlight → Arrived，失败进入 Failed。只允许无订单的角色购买；角色死亡、离开、远行归来和多次通讯均不删除购买记录。

到达 Letter 只由本订单的专用空投舱成功放出人物后触发。提交通知前先写入 Arrived 与 `arrivalLetterSent`；重复完成不再取得通知资格。代码不监听 Pawn 的 `SpawnSetup`、地图进入或商队返回，因此远行归来没有再次触发入口。通知过程异常时明确报错，不自动重发。

首次加入填满实际适用需求。技能、经历、特质、外观、基因、装备只在首次生成时设置；加入后按游戏规则成长、受伤和更换装备，读档不重新应用人物配置。

## 保存所有权与失败处理

| 对象 | 保存位置 |
| --- | --- |
| 已查看且未购买的实际 Pawn | 世界组件的 `pendingContents` 深度保存，按专用 PawnKind 从容器查询 |
| 待派遣舱 | 世界组件的 `pendingContents` 深度保存 |
| 待派遣 Pawn | 舱的 `ActiveTransporterInfo.innerContainer` 深度保存 |
| 飞行舱及人物 | 地图上的原版 Skyfaller 容器保存；从 pendingContents 转移后不再双重保存 |
| 已加入 Pawn | 原版地图、商队、世界人物或尸体等正常保存；订单只留引用 |
| 扣取的白银 | 订单 `payment` 深度保存，成功加入后销毁 |
| 唯一购买与通知标记 | 世界订单保存，独立于 Pawn 是否仍存在 |

Arrived 与 Failed 都清除不再使用的舱和地图引用。Pawn 引用不启用 `saveDestroyedThings`，已销毁者可以恢复为空，购买标记继续有效。

读档时 `World.FinalizeInit(true)` 早于地图加载和交叉引用恢复，不能在该回调中核验 Pawn／舱／地图。订单校验与派遣时间表恢复由 PostLoadInit 安排到加载长事件结束后执行，此时 Scribe 引用和地图实体都已初始化，避免把尚未恢复的正常引用误判为损坏。

目的地消失、载体损坏、生成或开舱失败时，订单终止并记录明确错误。可用地图中退回白银；无法放置或地图已移除时，费用保留在订单里，之后通过任一殖民地的 Hana 页面领取。失败状态不在 Tick 中循环重试。保存前检查未完成订单的目的地，避免写入已被移除地图及其载体的悬空引用。

每 Tick 只比较下一次派遣时间，到期时才处理订单；没有全世界 Pawn 扫描。空投销毁先完成基类销毁，再报告尚未完成的订单，失败清理不会递归重复销毁同一载体。

人物放置、开舱声音、落地故事和舱体内容清理由原版 `ActiveTransporter.Tick/PodOpen/Destroy` 执行。专用舱只在原版销毁后检查本订单的 Pawn 是否已经到达目标地图，并提交完成标记及一次通知。

撤销尚未完成初始化的生成时使用原版 WorldPawns.PassToWorld(..., Discard)。只调用 Pawn.Destroy 会将该 Pawn 放入 WorldPawns；Discard 流程同时销毁装备、解除引用和清除人物，不留下失败生成的世界人物。生成函数通过输出引用立即把 Pawn 和待转入物品交给世界组件的创建事务，提交容器失败时由 try/finally 清理，异常不被吞掉。未扣款的购买失败将同一实际 Pawn 转回世界组件容器；已扣款失败仍停止订单并退款，不重建人物。

首次联系 Hana 时建立空 pendingContents；首次打开详情时通过 PawnGenerator 创建实际人物，尚未指定玩家派系。直接按专用 PawnKind 从容器查询，不再维护第二份人物字典。再次查看取同一对象；购买使用原版 TryAddOrTransfer 移入派遣舱。到达后通过原版 SetFaction 加入玩家，随后填满需求并提交一次通知。

窗口只持有显示引用。返回和 PostClose 不销毁人物、不重新应用外观。未购买的角色不在 WorldPawns 列表，原版世界 Pawn GC 和 Tick 均不处理她，无需 KeepForever、GC 补丁或保活扫描。容器深度保存人物及所有 Comp，固定 Facial Animation 面部六项和主副眼色由控制器随 Pawn 保存，详情和派遣是同一个人。

未联系时的空容器可以为 null；读档不要求不存在的人物存储必须恢复。没有订单节点表示尚无订单，保留初始空列表；现有订单继续由原版恢复，加载完成后仅恢复订单父级、派遣引用与时间。人物只由容器、派遣舱或地图其中一个位置深度保存。已移除重复人物字典、工作列表及其完整性校验。

## 人物生成与依赖

满天星资料以 `pawnslots_提取核对.md` 为准。使用专用 PawnKind，关闭普通鼠族模板的口粮和随机装备，禁止复用世界 Pawn、随机亲属与额外年龄特质。`ForceNoGear` 与 `ForceNoIdeoGear` 阻止两个装备生成入口；意识形态和正常健康初始化仍由游戏处理。

2026-10-14 初始旧伤修复：五位特殊人物的 PawnKind 均配置原版 `allowOldAgeInjuries=false`。原版 `AgeInjuryUtility.GenerateRandomOldAgeInjuries` 在入口检查该字段并直接退出，因此不随机产生永久伤口、截肢或模拟历史生日疾病；`PawnGenerator.GenerateInitialHediffs` 的其余流程仍执行，基因、种族、装备 Hediff 继续由现有原版／模组通知处理。只增加五项 XML 配置，没有运行 C#、反射补丁、Hediff 清理、人物重建或持续检查；已生成者不自动治疗。

开发者快速启动的 `Root_Play.SetupForQuickTestPlay` 会替换 Current.Game 并创建世界，开局 Pawn 仍经 `StartingPawnUtility.NewGeneratedStartingPawn` 调用同一个 PawnGenerator，不能作为无旧伤生成器复用。本次直接使用原版 PawnKind 开关。

回归验证先在缺少该开关的配置上失败；增加字段后 943 项检查及 106 项唯一 Def 引用核对通过。验证对五份配置分别执行原版 XML 布尔字段解析，再实际调用旧伤函数，确认它在访问尚未建立的年龄／健康组件前直接退出。完整 Pawn 生成与游戏内渲染仍不在独立验证范围。来源：RIMSAGE PawnKindDef.cs:87、AgeInjuryUtility.cs:60-132、PawnGenerator.cs:1177-1313、Root_Play.SetupForQuickTestPlay、StartingPawnUtility.DefaultStartingPawnRequest/NewGeneratedStartingPawn（2026-10-14）。

固定清单包含 14 个内源基因，购买满天星需要 Biotech。没有该 DLC 时界面明确禁购，不将 Biotech 加为整个 MOD 的强制依赖。生成请求直接指定 `RK_XenoType_Ratkin`，原版异种提供 12 个常规基因，人物清单仅追加异种未包含的 `Skin_Melanin3`、`Hair_DarkReddish`。不再先生成 Baseliner 再修改异种身份。

`forcedEndogenes` 是追加清单，不限制原版产生其他基因。`Pawn_StoryTracker.SkinColorBase` 在无可用肤色基因时可添加随机基因，`GenerateGenes` 也会补充肤色、发色；首次固定外观初始化移除清单外的随机 Melanin／HairColor 基因，再验证最终清单。其他种族、能力或外源基因不被静默清除，真正不匹配时错误列出实际基因。

白银扣取使用 `stack.SplitOff(amount)` 后的无容器银堆，交给订单 `payment.TryAdd(Thing,bool)`。原版 `TryAdd(Thing,int,bool)` 在拆堆前会拒绝已有地图容器归属的对象；`TryAddOrTransfer` 转入 `TryTransferToContainer` 后也禁止直接从 Map 转移。整堆扣取会自动脱离地图，部分扣取保留原堆余额，订单继续负责深度保存和成功后的销毁。

技能先读取实际 Aptitude，再从最终目标反算基础等级并核验；采矿 4、种植 8 在 +4 资质下基础分别为 0、4，不重复加经历数值。派送箱走现有正常装备通知链路。

普通特质只配置在专用 PawnKind 的 forcedTraits 中，交由原版生成。移除原版额外随机生成的普通特质后核验固定清单，不维护第二份配置，也不在缺失时静默补填。指定极佳品质的物品缺少品质组件时明确报错，食物和白银的无品质状态按原版处理。

`TraitRequirement` 使用自定义 XML 解析，固定等级必须写成 `<Beauty>2</Beauty>`。`<li><def>Beauty</def><degree>2</degree></li>` 会被原版登记为名称 `Beauty2`，且没有等级；另外两项同理，人物 Def 的固定特质配置错误也是此解析失败的结果。2026-10-13 已修正三项 XML，无新特质 Def、补填或替代流程。

HAR 通过首次生成时的缓存反射调用 OverwriteColorChannel 和 addonVariants，不增加新的编译引用。只写 hair，然后设置 story.HairColor；HAR 首次访问 ColorChannels 会生成种族发色并写回 story，先设置 story 再初始化通道会丢失固定值。尾巴、左耳、右耳 variant 均为 0。

肤色使用活跃的纯白肤色基因的正常结果，不赋值 story.SkinColorBase／skinColorOverride，也不写 skin／skinBase 通道。原始 CE 的黄色肤色只是保存快照；此前把它作为强制覆盖，导致基因纯白结果被替换，现已删除两个废弃肤色配置字段和 XML 节点。CE 的眼色字段来自 Facial Animation，缺控制器时白色是占位，不写入 HAR eyes 通道。

FA 固定配置取自 D:\QQFL\pawnslots.txt 第 45、19、53 字段，涵盖六项面部类型和主副眼色。SpecialCharacterFacialAnimation 使用字符串配置，仅当 Nals.FacialAnimation 与 fxz.Ratkin.FacialAnimation 同时加载时执行反射解析，无 FA 编译依赖。通过公开 FaceType 属性指定实际类型，FaceColor/FaceSecondColor 指定眼色；全部固定值先于 InitializeIfNeed 写入，随后 SetDirty。缺失指定 Def 直接抛错，不使用 FaceTypeDefName 的静默失败 setter，不添加随机替代或 catch。肤色仍由故事／基因提供，Ratkin_SkinNormal 只是 FA 绘制类型。

旧原始人物槽和新 FA 导出分开取值：原配置 Thin、RK_HeadType_Head1；新文件普通头型为 RK_HeadType_Head3。此次仅导入 FA 字段，不替换普通头型、技能或装备数据。

## 交付前自验结论

1. 创建时间：按用户最新方案，首次打开详情生成实际人物。首页、世界初始化和读档不生成；再次查看、购买和派遣复用同一 Pawn，关闭窗口不销毁。购买前由世界组件深度容器持有，等待时转入舱内，飞行后由地图载体持有。不加入 WorldPawns，因此普通世界 GC 不清理；无需 KeepForever 或 GC 补丁。
2. 异常处理：本模块保持 3 处 catch，处理购买事务、发射和开舱失败；新增人物创建只有 try/finally 负责未提交对象的回收，异常继续抛出。未扣款失败保留实际人物，已扣款失败终止订单并退回或留存费用。静默替代、重新生成、补发、旧字段迁移及自动重试均为 0。
3. 设计取舍：复用原版异种生成、ThingOwner 保管／转移、Scribe 深度保存、SetFaction 加入、白银去重、SplitOff 拆堆、空投下落、开舱放人、声音、落地故事、装备通知和人物回收。已删除临时预览生成与销毁链路及黄色肤色覆盖字段。未购买人物不 Tick，没有 GC 扫描、保活补丁、反复初始化眼型或余额轮询。
4. Def：三个新增 Def 名称均使用字母、数字和下划线，无重复；完整类名及派遣舱继承关系可识别。普通字段按实际类型元数据核对，defaultFactionType 对应原版 LoadAlias；固定特质按原版自定义解析实际登记的名称和等级核对。此前单看字段的检查漏检了错误语法，本轮补上这一验证入口，54 项引用检查通过。
